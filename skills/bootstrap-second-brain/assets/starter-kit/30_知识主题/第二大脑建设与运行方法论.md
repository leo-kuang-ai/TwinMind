# 第二大脑建设与运行方法论

> 这是一份建设总纲，不是目录装修指南。它来自真实个人知识库的建设、运行与治理经验，但尚未在多个独立用户中验证，因此保持 `pilot`。目录、工具和自动化只是实现；可信知识进入真实行动，并依据结果修订，才是第二大脑开始工作的证据。

## 1. 核心判断

第二大脑不是文件仓库，也不是“知识库 + AI 问答”。一个可用系统应同时满足五项成功条件：

1. **保存事实**：原件、来源、时点和历史不丢失；
2. **形成知识**：能区分事实、推断、决定、方法和未知；
3. **支持行动**：知识能进入项目、决策、任务与交付；
4. **持续修订**：错误、冲突、过期和替代关系能被发现并处理；
5. **验证价值**：能用真实问题、行动结果和维护成本判断是否值得继续。

设计启发式：

```text
第二大脑价值 ≈ 任务成功率 × 可信度 × 连续性 × 复用率
               ÷ 获取成本 × 维护成本 × 错误风险 × 系统复杂度
```

这不是统计公式。它提醒我们：保存更多、搜索更强或自动化更多，都可能在没有真实收益时降低系统价值。

## 2. 两套视角不要混用

### 建设视角：三层设计

| 层 | 回答的问题 | 本 Demo 的主要承载 |
|---|---|---|
| 物理结构 | 内容放在哪里，能否恢复 | 九区目录、Markdown、附件、Git、备份 |
| 逻辑模型 | 内容是什么、何时有效、能否信任 | type、status、来源、时点、证据、owner、链接 |
| 运行机制 | 谁在什么条件下让内容进入、使用、修订和退出 | 协议、加载清单、任务契约、复盘、门禁、维护记录 |

正确顺序不是先设计完美目录，而是：

```text
真实目标与高价值问题
→ 事实 owner、权限和停止条件
→ 最小逻辑对象与状态
→ 最小物理结构
→ 真实内容试跑
→ 根据失败补能力
```

九区只是稳定职责边界，不是九种成熟度，也不应承担所有分类维度。项目、领域、角色和时间等多维关系优先用链接、少量字段与视图表达，不复制多个“当前版本”。

### 运行视角：一个事实核心、五种协同能力

```text
感知发现 → 认知定义 → 记忆供给 → 治理过滤 → 执行交付
                                      └→ 结果回写与修订
```

- **事实核心**：可读取的 Markdown、原件和版本历史；
- **感知**：导航、全文搜索、语义召回和事件提醒，只返回候选；
- **认知**：定义问题、目标、假设、选项和反例；
- **记忆**：保存来源、知识、决定、经验和方法；
- **治理**：决定当前能信什么、能加载什么、能修改什么；
- **执行**：把知识转为任务、交付和可观察结果。

这五种能力是逻辑职责，不要求增加五个目录。索引、向量、图谱和 AI 摘要都是可删除重建的投影，不能成为第二事实源。

## 3. 九区的稳定职责

| 目录 | 唯一主要职责 | 关键边界 |
|---|---|---|
| `00_待处理` | 未分流输入 | 不进入正式结论 |
| `10_当前工作台` | 当前目标、项目、决定和下一步 | 不替代外部业务事实 owner |
| `20_原始资料` | 原件与来源证据 | 摘要不能覆盖原文 |
| `30_知识主题` | 可复用认知、框架与方法 | AI 草稿默认不是当前事实 |
| `40_输出成果` | 面向对象的交付 | 交付完成不等于结论永远正确 |
| `50_Skills` | 可重复产生结果的能力 | 一次成功不能标记为成熟 |
| `60_任务系统` | 可重复运行的控制契约 | 文件存在不等于调度启用 |
| `90_模板` | 降低正确记录成本 | 无消费者字段不进入模板 |
| `99_维护记录` | 运行、错误、裁决与演进证据 | 不取代知识与任务的当前定义 |

## 4. 信任先于检索

检索命中只说明“找到了候选”，不说明“可以作为依据”。回答前至少检查：

1. 来源是否能回到原文；
2. 结论对应什么时点和口径；
3. 它是 `verified`、`inferred` 还是 `unverified`；
4. 是否存在冲突、替代或失效记录；
5. 当前任务是否有权限读取和使用；
6. 哪个系统或页面拥有当前事实。

冲突不能静默合并。分别保留来源、时点和口径，由 owner 裁决当前 authority；旧结论标记为 `superseded / rejected / archived` 后保留历史，但不进入默认回答。

## 5. 从知识到行动，再从结果回到知识

主闭环：

```text
真实问题 → 来源与证据 → Candidate → 核验与边界
→ 决策 / 项目 / 任务 → 行动 → 结果 → 偏差解释
→ 保留 / 收窄 / 修订 / 降级 / 淘汰
```

最小进化单元不是一篇完整文档，而是：

```text
一个模型 + 一个适用场景 + 一条行动规则
+ 一次真实结果 + 一次偏差解释
```

日循环 `任务规划 → 真实执行 → 总结 → 思考 → 进化` 是主闭环的短周期控制器：规划选择结果，总结保存事实，思考检查假设与反例，进化只提出 Candidate。任何一步都不能凭 AI 自评补造真实结果。

## 6. 四阶段建设

| 阶段 | 只解决什么 | 通过证据 |
|---|---|---|
| 15 分钟启动 | 场景、三个问题、事实 owner、权限、预算和九区 | 能说清服务什么问题，以及什么不做 |
| 7 天跑通 | 一条来源→知识→行动→结果链 | 结论可追溯，结果已回写，完成一次恢复演练 |
| 30 天验证 | 冻结装修，用真实问题持续运行 | 知识进入行动，错误内容被隔离，维护未超预算 |
| 按失败升级 | 只补反复出现的系统缺口 | 新能力优于原基线，且可停用、回滚和审计 |

第一阶段使用目录、文件名和全文搜索。只有真实评测持续证明关键词检索不足，并且索引可重建、权限可过滤、增益大于成本时，才增加结构化查询、语义检索、RAG 或图谱。

## 7. 如何判断是否真的有价值

三层必须分别验收：

- **物理层**：原件与派生内容分离；可看差异；备份和恢复真实可用；
- **逻辑层**：重要结论有来源、时点、证据和唯一当前 owner；旧内容不会污染当前回答；
- **运行层**：至少有一条决策—行动—结果回放，且维护成本可控；若声称某个方法已经形成可复用能力，还必须进入第二个独立场景并产生可复核结果。

建议用真实问题集记录：第一次回答是否可用、找到证据花多久、是否改变决定或行动、结果如何、需要多少维护时间。文件数、链接数、向量数量、检索分数和模型自评只能证明局部能力，不能单独证明价值。

## 8. 进化时优先问什么

当 Candidate、问题或实验开始超过人工注意力时，先用一个轻量排序器，而不是直接建设复杂“自学习系统”：

1. 回答这个问题会改变哪项行动、风险或状态？
2. 它能区分哪些竞争假设？
3. 是否可由本地确定性检查直接回答？
4. 现有来源、时点和权限是否足以解释答案？
5. 信息价值是否高于人工成本和执行风险？
6. 是否与本批其他问题重复？

每批最多三个问题，也可以为零。只有“候选太多、询问低效、实验排序差”成为可复现失败，并有历史样本和对照基线时，才评估贝叶斯主动学习或实验控制平面。即使后验很高，也只能生成处置建议，不能自动晋升知识、人格、协议、战略或 Skill。

## 9. 常见失败与停止条件

- 先建完美目录，再寻找问题；
- 收藏、摘要或链接数量代替知识化；
- 让摘要覆盖原件；
- 把检索命中或 AI 自信当作事实；
- 过早引入插件、向量、图谱和调度器；
- 自动化直接修改当前权威内容；
- 只评测搜索，不评测行动结果；
- 所有复盘都只得出“继续优化”；
- 知识库本身成为主要项目。

出现任一情况时暂停扩建：连续一个月没有真实使用；维护成本持续高于节省时间；新增字段、任务或视图没有消费者；同一事实出现多个当前 owner；自动化不可预览、不可撤销或不可审计；新技术没有改善真实任务指标。

## 10. 第一次使用的最小验收

- [ ] 明确首个真实场景、三个问题、权限和停止条件；
- [ ] 原件、知识、工作、任务与运行证据职责分离；
- [ ] 重要结论能回到来源、时点和证据等级；
- [ ] 一个真实问题完成了来源→知识→行动→结果回写；
- [ ] 旧结论、候选和未授权数据不会进入默认回答；
- [ ] Git 差异、备份和恢复至少演练一次；
- [ ] 维护时间没有超过启动契约预算；
- [ ] 能明确做出继续、收缩、替换或停止之一。
