# 60_任务系统

## 用途
保存驱动第二大脑持续运行、检查和进化的任务契约。每个任务都必须说清目标、触发方式、输入、输出、权限、人工门禁、失败信号和停止条件。

## 与其他目录的边界

- `10_当前工作台`：人正在推进的目标、项目和下一步动作；
- `50_Skills`：可重复调用的能力，回答“怎样做”；
- `60_任务系统`：运行契约，回答“为什么、何时、以什么权限调用哪项能力”；
- `99_维护记录`：任务运行结果、错误、人工裁决和修订证据。

## 放什么

- [[60_任务系统/00_任务注册表]]；
- 定时、事件触发或手工触发的可审阅任务定义；
- 任务与 Skill、输入路径、输出路径及真实调度器之间的引用。

## 默认日循环

```text
每日任务规划 → 真实执行 → 每日总结 → 每日思考 → 每日进化
```

- **每日任务规划**：从当前项目和事实 owner 中选出当日最多三个结果；
- **每日总结**：核对计划、行动、交付、阻塞与未完成事实；
- **每日思考**：选择一个高价值偏差或问题，检查假设、反例和未知；
- **每日进化**：将前三步转为最多三条知识、Skill 或任务修订 Candidate，不自动采纳。

## 不放什么

- 不放普通项目待办和临时 checkbox；
- 不保存调度器密钥、访问凭据或敏感参数；
- 不把每次运行报告堆在任务定义旁边；
- 不因为任务文件存在，就声称任务已启用、已调度或已产生价值。

## 生命周期

```text
draft → pilot → active → paused → retired
```

- `draft`：只有契约草案，没有运行证据；
- `pilot`：正在手工或受控试跑，不代表稳定；
- `active`：调度器事实 owner、权限、失败告警和停用方式均已核验；
- `paused`：暂停运行，保留契约和历史；
- `retired`：不再使用，说明替代方案或停止原因。

每档迁移的晋级/退役证据与双向核对流程见 [[60_任务系统/00_任务注册表]]；任务定义页的审计字段（prompt 快照、摘要哈希、事实源声明）记录"谁在真实执行"，与状态列互相独立。希望把任务接入 WorkBuddy 定时执行时，参考 [[60_任务系统/20_WorkBuddy接入映射]]（可选路径，不改变默认不接调度器的边界）。

## 最小动作

1. 从 [[90_模板/任务契约模板]] 创建 `draft`；
2. 先手工运行，把输出和裁决记录到 `99_维护记录/`；
3. 同一流程连续稳定两周，再评估是否接入真实调度器；
4. 启用、扩权、修改事实 owner 或执行高风险写入前，必须获得人工确认。
