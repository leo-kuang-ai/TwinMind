# 记忆系统

> 原则：分身没有跨会话记忆——这个 Vault 就是它的记忆。会话里产生的结论如果不落盘，下次等于没发生。记忆系统的全部职责就两件事：**把会话沉淀成可回放的记录，把稳定经验提升成可注入的记忆**。

## 一、会话收尾契约

任何一段实质性工作结束前，三件事必须发生，缺一不可：

1. **结论落盘**：重要结论写入对应知识页或项目页，"只存在于对话里"等于没发生；
2. **记录留档**：在 `记忆系统/会话/` 下留一份会话交付记录（模板见下节）；
3. **变更提交**：修改过的文件进入版本历史，可回放。

## 二、会话交付记录模板

存于 `记忆系统/会话/YYYY-MM-DD-主题.md`：

```markdown
# YYYY-MM-DD 会话交付记录：____（主题）

- 目标：本次会话要解决什么
- 交付：做了什么、产出了哪些文件（逐个列出路径）
- 验证：怎么确认是对的（跑了什么检查、对照了什么来源）
- 边界：什么没做、哪些判断是推断、哪些待 Owner 决定
- 链接：相关知识页 / 项目页 / 来源
- 下一步：交给谁、等什么、何时回看
```

## 三、记忆条目（跨会话复用的最小记忆单元）

### 条目四级

| 级别 | 存什么 | 例 |
| --- | --- | --- |
| 工作 | 当前目标、范围、检查点 | 项目推进状态 |
| 程序 | 怎么做某类事的方法 | "发布前必跑的三步检查" |
| 语义 | 稳定的事实与结论 | "xx 系统的部署口径" |
| 情景 | 当时为什么那样决定 | 某次取舍的背景 |

### 条目模板

存于 `记忆系统/条目/MEM-CAND-YYYYMMDD-主题.md`：

```markdown
---
id: MEM-CAND-YYYYMMDD-主题
type: 工作 | 程序 | 语义 | 情景
status: candidate        # candidate → confirmed → retired
source: 会话记录/项目页/来源页 的链接
as_of: YYYY-MM-DD
injectable: false        # confirmed 后按需改 true
---

（一条可独立复述的记忆：不超过 5 行，写清"什么条件下做什么"）
```

### 提升五检（candidate → confirmed 前逐项过）

1. **来源真实**：能回链到会话记录或来源页；
2. **时点明确**：带 as_of，不写成永久事实；
3. **无未决冲突**：与现有知识页不冲突，或冲突已按协议登记；
4. **注入安全**：注入上下文不会误导（不含过期口径、不含敏感信息）；
5. **权限合规**：不含越权内容。

**程序记忆（怎么做事的方法）提升必须 Owner 确认**——方法一旦确认，分身会按它行事，错的代价最高。

### 使用规则

- `candidate` 条目不得作为回答或决策依据（同协议 Candidate 纪律）；
- 检索按问题意图在工作/程序/语义/情景与原始来源之间选择，不承诺固定顺序；
- 每季度反熵审查时清理：连续两个季度未复用的 confirmed 条目标记 `retired`，不删除。

## 四、与既有闭环的关系

- 不新增调度、不新增目录层级：记录与条目由现有"每日总结 / 每日进化"任务和每周维护动作顺带沉淀；
- 候选条目的主要来源是 [[30_知识主题/从可信记忆到决策学习系统|决策学习系统]] 的最小进化单元与 [[60_任务系统/10_任务定义/每日进化|每日进化]] 的 Candidate 产出——本页只补"存成什么样、何时可复用"这一段；
- 分身人格相关记忆（偏好、盲点、风格）不存条目，直接更新 [[10_当前工作台/00_数字分身画像|数字分身画像]]。
