# 七天冷启动与三十天验收清单

> 目标：由《附录 B：七天冷启动 + 三十天验收清单》按当前 Demo 校准。先跑通一个真实闭环，再决定是否升级；第一周不全量迁移、不上 RAG、不开放 AI 高风险写入。

## 启动前

- [ ] 已填启动契约：场景、三个问题、事实 owner、权限、预算、停止条件
- [ ] 明确第二大脑不替代项目管理、CRM、日历等业务事实源
- [ ] 明确 Candidate 不能自动变成当前事实

## 七天冷启动

| 天 | 当天唯一目标 | 完成信号 |
|---|---|---|
| D1 | 写首个场景和 10 个真实查询 | 有当前耗时、入口和失败基线 |
| D2 | 建九区、控制文件、Git 与恢复副本 | 能看 diff，并在副本恢复 |
| D3 | 启用五个核心模板，只迁移三个问题 | 原件与结论分离 |
| D4 | 建一个项目首页和真实决定 | 一页看到目标、风险、下一步 |
| D5 | 测 10 个正向问题和 2 个负向问题 | 返回来源，草稿和旧结论不混入 |
| D6 | 手工跑来源→知识→行动→结果 | 会话有证据，Candidate 最多 3 条 |
| D7 | 完成首次复盘与决策回看 | 删除一个无价值复杂度，或记录“无可删” |

> 第一周的两条闭环是衔接关系：上表五步闭环（D1–D7）打基础；从 D6 起可并行跑"登记任务 → 执行留回放 → 周报"三产物闭环（用 [[90_模板/周报模板]] 收口）。前者解决材料可信，后者解决运转节奏。

## Day 8—30：冻结装修

- [ ] 不新增全局目录、字段、插件和自动化，除非同一失败反复出现
- [ ] 记录至少 12 个高价值真实问题
- [ ] 记录第一次回答是否可用、结论是否可追溯、是否进入行动、维护耗时
- [ ] 每周清理 `00_待处理/`，每次交付留下复盘记录
- [ ] 只修影响真实任务的高价值缺口

## 三十天验收

### 物理结构门
- [ ] 原件与知识分层；核心文件可读；索引可重建；完成恢复演练

### 逻辑与信任门
- [ ] 重要结论有来源、时点和证据；Candidate、旧结论不会混入当前回答

### 运行价值门
- [ ] 高频问题能找到可信材料；至少一次决定—行动—结果回放；维护未超预算

## 到期只做四种决定

- [ ] 继续：真实有效且成本可控
- [ ] 收缩：闭环有效但系统太重
- [ ] 替换：问题存在但工具持续制造摩擦
- [ ] 停止：没有真实使用，或成本长期高于收益
