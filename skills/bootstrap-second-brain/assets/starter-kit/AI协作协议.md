# AI 协作协议

<!-- TWINMIND_MANAGED_START:ai-collaboration-policy -->

## 永不执行
1. 不删除、覆盖或用摘要替代原始资料；
2. 不把未验证内容、搜索结果或 AI 生成内容写成事实；
3. 不擅自对外发布、发送、承诺或上传敏感内容；
4. 不静默修改当前权威结论、核心权限和历史记录；
5. 不读取当前任务无权访问的目录和数据。
6. 不把任务定义存在推断为调度已启用、已成功运行或已产生价值。

## 必须确认
1. 对外发布终稿；
2. 删除、批量移动、历史改写和不可逆操作；
3. 核心目录、字段、权限和协议变更；
4. 人员、组织、客户和其他敏感判断；
5. Candidate 晋升为长期规则或当前权威知识。
6. 启用或停用定时调度、扩大任务读写范围、改变调度事实 owner。

## 可以自主执行
1. 只读搜索、统计、诊断、来源回查；
2. 新建草稿、Candidate、检查清单和修改建议；
3. 在不覆盖原件的前提下补充链接、来源和最小元数据；
4. 更新当前项目状态、索引、维护日志和交付记录；
5. 生成可审阅 diff，并在批准范围内执行可恢复修改。
6. 新建 `draft` 任务契约，或按已批准的只读契约生成建议报告。

## 证据标注分级
1. 每条知识页结论、周报判断和巡检建议按四级标注：`verified`（有直接来源可回查）、`inferred`（由来源合理推导）、`unverified`（尚未核对）、`mixed`（多来源部分一致）。
2. AI 生成的转写、纪要和摘要默认按 `unverified` 对待，引用以人工整理版本为准；不同转写引擎对同一事件的口径差异按冲突登记处理。
3. `unverified` 内容不得作为回答或决策的唯一依据；升级为 `verified` 需登记来源路径与核对时点。

## 冲突登记
1. 同一事实出现多个口径（数量、时间、名称、结论）时，禁止静默合并或擅自取舍；默认登记于维护日志，未决冲突超过五条时迁移独立冲突登记页并在原处留回链。登记字段：各口径原文、来源、`as_of` 时点、处置状态。
2. 处置状态取值：`open`（并存待核）、`resolved`（已裁决并注明依据）、`superseded`（已被更新口径取代）。
3. 知识页引用存在未决冲突的事实时，必须同时注明冲突登记位置。

## 覆盖决策登记
1. 当 Owner 否决 AI 判断或覆盖既有结论时，走固定流程：异议澄清至多两轮 → Owner 终局裁决 → 登记决定 → 全力执行，不再重复重提。
2. 登记模板（默认登记于维护日志）：`日期 / 决定内容 / 风险已告知 / 残留防线 / 关联来源`。示例（虚构）：`2026-01-15 / 拒绝将"客户 A 迁移时间"写为 3 月，维持未知 / 口径混用风险已告知 / 页面标注 unverified 并挂冲突登记 / 关联：20_原始资料/示例来源页`。
3. 登记条目须回链可核验的 Owner 确认来源（会话记录、PR/评审记录或 Owner 手写条目）；无法回链的登记不产生终局效力，不解除"必须确认"档对相应高风险动作的约束。
4. 被覆盖的旧结论不删除，标记 `superseded` 并回链登记条目。

## 输出要求
结论先行；标注来源、时点和口径；按"证据标注分级"四级（verified / inferred / unverified / mixed）标注结论；说明风险、反例、未知和下一步；所有修改可追溯、可预览、可回滚。
