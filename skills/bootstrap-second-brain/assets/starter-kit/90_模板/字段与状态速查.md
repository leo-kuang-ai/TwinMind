# 字段与状态速查

> 用途：新建内容时判断最少填什么。依据外部长文《个人第二大脑搭建指南》附录 A 按当前九区架构校准；字段服务于检索、审核和执行，不为“看起来完整”而增加。

## 启动期七个核心字段

| 字段 | 回答的问题 | 示例 |
|---|---|---|
| `type` | 这是什么载体 | source / knowledge / project / decision / task / session |
| `status` | 当前处于什么阶段 | candidate / active / monitoring |
| `created` | 何时创建 | YYYY-MM-DD |
| `updated` | 何时更新 | YYYY-MM-DD |
| `as_of` | 结论针对什么时点 | YYYY-MM-DD |
| `evidence_level` | 证据可信度如何 | verified / inferred / mixed / unverified |
| `sources` | 依据在哪里 | 内部链接数组 |

不是每种文件都必须填满七项：来源页可用 `source_url`，项目页重点是状态和复核，知识与决策页必须重视 `as_of`、证据和来源。

任务契约另外需要 `task_id`、`task_type`、`scheduler_owner`、触发、权限、失败信号和停止条件。调度器未接入时，`scheduler_owner` 保留为 `unassigned`，不得把建议触发时间写成已启用事实。

## 知识页与来源页治理字段（必填）

| 字段 | 回答的问题 | 取值示例 | 消费者 |
|---|---|---|---|
| `authority` | 这条结论的事实权威是谁 | personal（个人判断）/ source（以外部来源为准）/ owner-confirmed（经事实 Owner 确认） | 读者与 AI 判断引用权重 |
| `review_at` | 何时到期复核 | YYYY-MM-DD；到期后由到期巡检列出 | 到期巡检（`review_due.py` 与巡检流程） |
| `evidence_note` | 证据边界一句话 | 依据哪条来源、核对到什么程度 | 证据分级与冲突登记 |

其他页面类型（项目、决策等）可按需增加 `review_at`；填了就会进入到期巡检。占位日期与非法日期的跳过规则以 [[30_知识主题/到期巡检与到期处置]] 为准，填了真实日期即生效。

## 内容级密级（可选标注）

`confidentiality` 标注页面内容敏感度：`public / internal / confidential / private`。注意它与初始化期的数据域（`restricted / confidential / session_only`）不是同一概念：数据域管"访谈数据是否持久化"，密级管"这页内容本身多敏感"。密级是用户自主标注，系统不自动分类、不强制、不因标注改变数据域处理；每周体检的清点项只汇总显式标注页面，不输出未标注页面的密级推断。

## 有真实需求后再增加

| 字段 | 何时增加 |
|---|---|
| `owner` | 多人协作或责任边界不清 |
| `injectable` | 需要控制是否进入 AI 上下文（消费者：加载清单） |
| `supersedes` | 新结论替代旧结论 |
| `contradicts` | 多个结论存在冲突 |

## 状态怎么选

| 状态 | 使用方式 |
|---|---|
| `draft` | 尚未完成，不进入正式回答 |
| `candidate` | 值得验证，但不是事实 |
| `active` | 普通内容当前有效 |
| `adopted` | 经明确门禁采纳，并已更新唯一规范页 |
| `pilot` | 任务或能力正在受控试跑，尚不代表稳定 |
| `paused` | 任务暂停运行，保留契约与历史 |
| `monitoring` | 有冲突、缺口或等待结果 |
| `rejected` | 明确不采用，只保留历史 |
| `superseded` | 已被新结论替代 |
| `archived` | 结束维护，不进入当前上下文 |
| `retired` | 任务或能力已退役，保留替代方案或停止原因 |

## 三条底线

1. 新知识默认从 `candidate` 开始，不默认写成 `verified`；
2. `canonical` 表示唯一事实所有权，不是"内容写得完整"，不要默认设为 `true`；
3. 来源页的 `verified` 只证明原文、出处和完整性已核对，不证明作者所有主张都正确。

## 字段与术语对照

| 本库用语 | 对应/来源 | 说明 |
|---|---|---|
| 治理字段（authority / review_at / evidence_note） | 源方法论五字段中的三个 | `injectable` 按需增加（消费者：加载清单）；`lens` 面向多视角组织，单用户场景暂不引入 |
| 审计字段（prompt_snapshot / prompt_sha256 / execution_source） | 任务契约 `scheduler_owner` 的扩展 | 声明"谁在真实执行任务"：未接入时三字段均为 unassigned；接入后 execution_source 写调度器名（事实源），库内页面为审计副本，prompt_sha256 登记所配置 prompt 的摘要哈希 |
| 任务状态（draft / pilot / active / paused / retired） | 状态表的五档 | 每档迁移需按任务注册表的启用门禁声明晋级证据，默认停留在 `draft` |
| 内容级密级（confidentiality） | 初始化数据域的日常层 | 见"内容级密级"节；两者不是同一概念，互不改变对方处理 |
