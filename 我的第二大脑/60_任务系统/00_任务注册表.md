## 生命周期迁移门禁

每次状态迁移都需要登记对应证据；证据记录回链 `99_维护记录/`，登记时点含时区。

| 迁移 | 需要的晋级/迁移证据 |
|---|---|
| `draft → pilot` | 契约定稿 + 至少一次手工运行记录（输出与裁决可回链来源） |
| `pilot → active` | 下方启用门禁五条全部完成 + 连续两周稳定试跑记录 + 人工明确批准 |
| `active → paused` | Owner 暂停决定 + 恢复条件声明 |
| `paused → active` | 恢复条件复核 + 一次受控复跑记录 |
| `active / paused → retired` | 替代方案或停止原因 + 零使用周期声明 |

### 启用门禁（进入 active 的五条）

1. 确认真实调度器和配置的唯一事实 owner；
2. 记录当前时区、触发节奏和可核验的调度收据；
3. 核验输入、输出、排除范围、权限和停用方式；
4. 至少完成一次受控试跑，且运行记录能回到来源和输出；
5. 人工明确批准启用。

### 违规示例（不可接受的状态声明）

- 任务页写"已配置 WorkBuddy，可视为 active"——调度器配置不等于启用证据，仍缺五条门禁；
- 任务页写"已有 prompt 快照和哈希，故视为已启用"——审计字段只证明契约可追溯，不构成运行证据；
- 注册表状态列与任务定义页 `status` 不一致时，以人工复核为准，禁止静默改齐。

## 双向核对（登记 vs 实际运行）

定期（建议每月）做一次双向核对，输入必须是用户手动提供的调度器侧导出清单或用户自查结果——AI 不因此获得任何外部系统的连接、读取或写入授权：

1. 外部 → 库内：调度器侧每个任务都能在注册表找到登记，漏登则补登并记维护日志；
2. 库内 → 外部：注册表每个非 `draft` 任务都能在调度器侧找到对应，找不到则标记漂移并复核状态；
3. 核对完成后在注册表登记快照时点（`snapshot_at: YYYY-MM-DD HH:MM +HH:MM`）。
