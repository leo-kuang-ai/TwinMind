# 工具选择与升级门禁

> 配套目录：[[第二大脑完整工具清单]]回答“有哪些工具”；本页只回答“什么时候才应该增加”。

> 由《附录 D：工具与技术栈选型》提炼，移除了易过期价格、版本和固定规模阈值。工具不是第二大脑本身：先选能保存、查找、审计和恢复的最小组合，再由真实失败决定升级。

## 第一版只需要

- 本地 Markdown 与文件系统；
- Obsidian 负责编辑、导航和全文搜索；
- Git 或其他可恢复版本历史；
- AI 协作统一使用 WorkBuddy，初期只读取指定目录并生成草稿。

Obsidian 适合个人长期本地知识；Notion、Confluence 等更适合团队协作和展示。它们可以并存，但同一类事实必须有明确 owner。

## 升级信号

| 反复出现的真实问题 | 再考虑增加 |
|---|---|
| 新建内容经常漏字段 | 模板自动填充工具 |
| 需要按状态、日期批量筛选 | 结构化查询或 Dataview |
| 准确关键词仍稳定漏召回 | 语义检索，并先做问题基线 |
| 多设备读取成为高频需求 | 同步方案，并完成冲突与恢复测试 |
| 同一步骤稳定重复至少两周 | 提醒、定时任务或自动化 |
| 一个方法在两个独立场景有效 | Skill 或标准工作流 |

## 启用任何工具前五问

1. 它解决了哪个可复现的真实失败？
2. 它会读取、上传或修改什么数据？
3. 它把索引、缓存和运行状态写到哪里？
4. 失败如何被发现，谁负责处理？
5. 如何停用、删除派生数据并恢复？

## 安全与恢复边界

- “本地应用”不等于所有插件和模型调用都在本地；
- 同步不等于备份，备份不等于已经验证可恢复；
- 私有仓库不等于不会泄露，仍需设备加密、最小权限和账号保护；
- 密钥、缓存、向量索引和可重建运行态不进入 Git；
- 涉及公司、客户或第三方数据时，按权限拆分存储域，不靠标签代替访问控制。

## 不使用固定价格和规模阈值

模型价格、插件许可和产品能力会变化；“笔记超过多少篇就上向量库”也没有通用答案。以自己的真实问题、漏召回样本、维护成本和恢复能力做决定。
