# 字段与状态速查

> 用途：新建内容时判断最少填什么。由《附录 A：目录与字段参考手册》按当前九区架构校准；字段服务于检索、审核和执行，不为“看起来完整”而增加。

## 启动期七个核心字段

| 字段 | 回答的问题 | 示例 |
|---|---|---|
| `type` | 这是什么载体 | source / knowledge / project / decision / task / session |
| `status` | 当前处于什么阶段 | candidate / active / monitoring |
| `created` | 何时创建 | YYYY-MM-DD |
| `updated` | 何时更新 | YYYY-MM-DD |
| `as_of` | 结论针对什么时点 | YYYY-MM-DD |
| `evidence_level` | 证据可信度如何 | verified / inferred / mixed / unverified |
| `sources` | 依据在哪里 | 内部链接数组 |

不是每种文件都必须填满七项：来源页可用 `source_url`，项目页重点是状态和复核，知识与决策页必须重视 `as_of`、证据和来源。

任务契约另外需要 `task_id`、`task_type`、`scheduler_owner`、触发、权限、失败信号和停止条件。调度器未接入时，`scheduler_owner` 保留为 `unassigned`，不得把建议触发时间写成已启用事实。

## 有真实需求后再增加

| 字段 | 何时增加 |
|---|---|
| `review_at` | 内容会过期，需要定期复核 |
| `owner` | 多人协作或责任边界不清 |
| `injectable` | 需要控制是否进入 AI 上下文 |
| `supersedes` | 新结论替代旧结论 |
| `contradicts` | 多个结论存在冲突 |

## 状态怎么选

| 状态 | 使用方式 |
|---|---|
| `draft` | 尚未完成，不进入正式回答 |
| `candidate` | 值得验证，但不是事实 |
| `active` | 普通内容当前有效 |
| `adopted` | 经明确门禁采纳，并已更新唯一规范页 |
| `pilot` | 任务或能力正在受控试跑，尚不代表稳定 |
| `paused` | 任务暂停运行，保留契约与历史 |
| `monitoring` | 有冲突、缺口或等待结果 |
| `rejected` | 明确不采用，只保留历史 |
| `superseded` | 已被新结论替代 |
| `archived` | 结束维护，不进入当前上下文 |
| `retired` | 任务或能力已退役，保留替代方案或停止原因 |

## 三条底线

1. 新知识默认从 `candidate` 开始，不默认写成 `verified`；
2. `canonical` 表示唯一事实所有权，不是“内容写得完整”，不要默认设为 `true`；
3. 来源页的 `verified` 只证明原文、出处和完整性已核对，不证明作者所有主张都正确。
