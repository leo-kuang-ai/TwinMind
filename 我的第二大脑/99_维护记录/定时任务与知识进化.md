# 定时任务与知识进化

> 原则：先手工跑通，再自动提醒。第一版不需要定时任务；只有运行节奏已经稳定、重复维护成为负担时，才接入自动化。

## 1. 四阶段建设路线

| 阶段 | 你要完成什么 | 通过信号 |
|---|---|---|
| 15 分钟启动 | 契约、九区、三个真实问题 | 能说清首个场景、事实 owner 和权限 |
| 7 天跑通 | 一条来源→知识→项目/决策→交付→结果链 | 结论可回到来源，结果已回写 |
| 30 天验证 | 冻结目录与字段，用真实问题持续运行 | 维护成本在预算内，知识真实进入行动 |
| 按失败升级 | 只补反复出现的系统缺口 | 新能力解决了可复现问题，并可停用回滚 |

## 2. 推荐运行节奏

下面是菜单，不是第一天必须全部启用的任务。

| 周期 | 建议任务 | 系统产出 | 人的责任 |
|---|---|---|---|
| 每天 | 待处理提醒 | 新增、积压和未分流数量 | 删除、分流或明确延后 |
| 每天开始前 | 每日任务规划 | 最多三个结果、第一动作、最大风险 | 确认优先级和对外承诺 |
| 每天结束后 | 每日总结 | 完成、延期、交付、决策与阻塞事实 | 确认完成状态和下一步 |
| 每日总结后 | 每日思考 | 一个高价值问题、反例、未知和小实验 | 判断哪个问题值得继续追问 |
| 每日思考后 | 每日进化 | 最多三条知识、Skill 或任务修订 Candidate | 采纳、验证或拒绝，不自动晋升 |
| 每周一 | 本周计划 | 当前项目、截止日期、阻塞 | 选择本周最多三个结果 |
| 每周五 | 周复盘 | 完成、延期、决定、失败 | 判断原因并回写项目和知识 |
| 每周 | 知识蒸馏 | 高频主题、冲突、Candidate 建议 | 最多保留 3 条，逐条核验 |
| 每月 | 健康检查 | 缺来源、过期复核、失效链接、重复职责 | 只修高价值问题 |
| 每季度 | 反熵治理 | 无消费者字段、无收益插件、未触发规则 | 删除或收缩复杂度 |

### 第一阶段最小节奏

只保留两个动作：

1. 每周清理一次 `00_待处理/`；
2. 每次真实交付后，在 `99_维护记录/` 写目标、结果、证据、风险和 Candidate。

连续两周能够手工完成，再考虑添加提醒。

## 3. 知识如何进化

```text
信号 → 保存来源 → 提炼 Candidate → 核验来源 / 时点 / 冲突 / 权限
→ active / adopted → 进入真实任务 → 记录结果 → 复核
→ 保留 / 修订 / superseded / archived
```

### 每个状态意味着什么

- `candidate`：值得验证，不是当前事实；
- `active`：普通内容当前有效；
- `adopted`：经过明确门禁，并已更新唯一规范页；
- `monitoring`：存在缺口、冲突或等待结果；
- `superseded`：已被新结论替代，保留历史；
- `rejected / archived`：不再进入当前回答，只供追溯。

### Candidate 晋升五问

1. 来源在哪里，能否回到原文？
2. 结论针对什么时点，何时可能失效？
3. 是否与现有知识冲突，哪个才是当前 owner？
4. 是否允许进入当前任务和 AI 上下文？
5. 是否有真实使用结果，而不只是“看起来正确”？

任何一问没有答案，就保持 `candidate` 或进入 `monitoring`。一次交付最多提取 3 条，也可以为零。

### 用结果偏差驱动三环进化

知识进入真实任务后，不要只记录“用过”，还要比较预期与实际：

```text
知识学习环：知识 → 模型 → 边界
真实任务环：问题 → 判断 → 行动 → 结果 → 偏差
系统进化环：偏差 → 补证 / 反证 → 保留 / 修订 / 降级 / 淘汰
```

一次回放最少回答六件事：目标任务、当前模型与假设、采取的行动、实际结果、偏差及替代解释、下一步修订。具体方法见 [[30_知识主题/从可信记忆到决策学习系统]]。

如果失败表现为“想不起来、解释不了、不会迁移、因果错误、边界过宽、旧模型失效或同类错误重复”，使用 [[30_知识主题/七阶学习闭环]] 选择需要退回的认知动作，不新增平行目录和状态。

## 4. 能力如何进化

知识回答“现在相信什么”，能力回答“下次怎样重复产生结果”，两者不要混用。

```text
一次任务成功 → 提炼检查清单 → 第一次复用：pilot
→ 修订输入、边界和失败模式 → 第二个独立场景
→ 取得可复核结果：proven → 模板 / Skill / 自动化
→ 被更好方法替代：retired
```

一次成功不能直接标记为 `proven`；安装工具、写出提示词或生成模板，也不等于能力已经形成。

## 6. 什么时候可以自动化

同时满足以下条件再启用：

1. 同一手工步骤至少稳定重复两周；
2. 输入、输出、权限和失败信号已经明确；
3. 自动化失败能被发现，且可以停用、回滚。

以下动作始终保留人工裁决：删除原件、合并知识、修改权限、晋升 Candidate、改变唯一事实 owner、对外发布。

## 7. 三十天后的唯一四种决定

- **继续**：真实使用，结果有效，维护成本在预算内；
- **收缩**：闭环有价值，但目录、字段或自动化太重；
- **替换**：问题存在，但当前工具持续制造摩擦；
- **停止**：没有真实使用，或维护成本长期高于收益。

> 系统进化的标准不是“功能越来越多”，而是“同类问题解决得更快、更可信，并且维护成本可控”。
