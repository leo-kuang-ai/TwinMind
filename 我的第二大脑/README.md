# 我的第二大脑：从这里开始

这套骨架的目标不是保存更多笔记，而是让可靠知识进入真实工作，并根据结果持续修正。

## 第一次使用

1. 阅读 `AI协作协议.md`，明确边界；把本文件夹交给任意 AI 宿主时，让它先读 `AI协作协议.md` 与 `加载清单.md`；
2. 填写 [[10_当前工作台/00_第二大脑启动契约]]；
3. 在 `00_待处理/` 写下三个真实问题；
4. 选择一个问题，用 `90_模板/` 跑通来源 → 知识 → 项目/决策 → 交付（去向：来源页存 `20_原始资料/`、知识页存 `30_知识主题/`、项目/决策页存 `10_当前工作台/`、交付复盘存 `99_维护记录/`）；
5. 在 `99_维护记录/` 留下结果、风险和最多 3 条 Candidate。

## 建设顺序

| 阶段 | 目标 | 暂时不要做 |
|---|---|---|
| 15 分钟 | 契约、九区、三个问题 | 插件、RAG、自动化 |
| 7 天 | 跑通一个真实闭环 | 全量搬家、增加大量字段 |
| 30 天 | 冻结装修，用真实问题验证 | 因为“先进”而升级 |
| 真实失败出现后 | 按缺口增加检索、Skills 或定时任务 | 自动删除、合并、晋升知识 |

## 每周 30 分钟三步卡

从第二周起，用这三步维持库的运转（预算超了就收缩，见周报模板的维护耗时小节）：

1. **到期巡检**：让 AI 宿主按 [[30_知识主题/到期巡检与到期处置]] 列出到期页（无需脚本）；或在 TwinMind 仓库运行只读脚本 `review_due.py`；
2. **五项体检**：照 [[99_维护记录/每周知识体检清单]] 逐项过，异常按处置指引；
3. **填周报**：复制 [[90_模板/周报模板]]，四小节含维护耗时与收缩决定。

## 运行入口

- 目录职责：阅读九个顶层目录各自的 `README.md`；
- 建设总纲：先读 [[30_知识主题/第二大脑建设与运行方法论]]，理解三层设计、价值闭环与停止条件；
- 当前工作：从 `10_当前工作台/` 开始；
- 运行任务：从 [[60_任务系统/00_任务注册表]] 查看任务状态和契约；
- 模板与字段：见 `90_模板/` 和 [[90_模板/字段与状态速查]]；
- 七天冷启动与三十天验收：见 [[99_维护记录/七天冷启动与三十天验收清单]]；
- 建设节奏、定时任务与知识进化：见 [[99_维护记录/定时任务与知识进化]]；
- 把知识转化为能力：见 [[30_知识主题/七阶学习闭环]]；
- 用真实结果修订知识和判断：见 [[30_知识主题/从可信记忆到决策学习系统]]；
- 高价值知识的学习与回放：复制 [[90_模板/高价值知识学习与回放模板]]；
- 到期巡检与处置：见 [[30_知识主题/到期巡检与到期处置]]（只读脚本 `review_due.py` 的用法在同一页）；
- 每周知识体检与周报：见 [[99_维护记录/每周知识体检清单]] 与 [[90_模板/周报模板]]；

> 任务定义存在不等于定时调度已启用。先手工跑通，再自动提醒；自动化只发现问题，不替人做高风险裁决。
